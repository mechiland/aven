# Aven 0.4.0 — install and update without rebuilding an ISO

Aven now has a separate, signed component update channel for Fedora Kinoite 44
x86_64. Install it on an existing Kinoite system, or adopt an existing Aven ISO
installation. Later changes use `aven update` and download only changed component
archives. Fedora system deployment, security updates and rollback remain under
rpm-ostree.

Download `Aven-Installer.tar.gz` and check it against `SHA256SUMS`. Extract it and
run from Konsole as the desktop user, with the focused applications closed:

```sh
tar -xzf Aven-Installer.tar.gz
python3 aven-installer/aven.py install
```

If the installer stages system dependencies, reboot and run
`~/.local/bin/aven update` to finish. Later use `aven check` or `aven update`.

Ordinary updates retain user preferences, panel arrangement, pinned applications,
mail accounts, bookmarks and personal files. An explicit
`aven update --reset-defaults` reapplies the current defaults/layout.
`aven recover` handles an interrupted application; `aven rollback` restores the
previous Aven profile release. Log out of Plasma before either restore operation.

This is an experimental Union release with the existing Plasma 6.8 Beta
dependency. The initial platform setup can require roughly 440 MB of RPMs plus
any missing Fedora applications/fonts. Those packages are mirrored as immutable
objects in this channel; theme-only updates do not redownload them.

The updater has been exercised on a disposable clone of the official booted
Kinoite baseline, including dependency staging/reboot, initial profile install,
successive component updates, configuration/data preservation, failure recovery
and profile rollback. A theme-only test update transferred 20,749 bytes. This is
a delivery test, not a new visual score or a claim that every future update will
have that size. Union's visual scores remain pending.

The fixed channel tag is a prerelease. It does not supersede the offline ISO as
GitHub's latest release. Keep the installed signing key; future releases are
verified against it. See `docs/ONLINE-UPDATES.md` in the source repository for
the maintainer build/publish commands and supported application versions.
